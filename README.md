# Mac標準「メール」アプリ用 AIフィッシング自動振り分けツール

毎回異なる送信元アドレス・異なる企業名で送られてくるフィッシングメールを、**ヘッダー認証解析（SPF/DKIM/DMARC・URL偽装検知）＋ ローカル大量送信/無意味メール検知 ＋ Gemini API（`gemini-3.5-flash-lite`）** で自動判定し、Mac標準の「メール」アプリ（Mail.app）で迷惑メールへ振り分けます。

Mail.app に登録されている全アカウント（IMAP / POP / Gmail / iCloud / 各種プロバイダメール等）に自動対応します。

## 主な特徴

- **なりすまし矛盾を自動検知**: 表示名・本文の企業名と、実際の送信元ドメイン・`Return-Path`・リンク先ドメインの矛盾を抽出して Gemini に判定させます。
- **バッチ一括判定＆自動リトライ**: 複数メールをまとめて1リクエスト（デフォルト10通/リクエスト）で判定し、HTTP 429/503 時は自動待機してリトライします。
- **プライバシー配慮**: Gemini Interactions API を `store=False` で呼び出すため、APIサーバーに履歴を保持しません。APIキーは macOS キーチェーンに保管し、設定・ログ・キャッシュは `~/.config/mail-phishing-filter/` に分離保存します。
- **誤判定防止＆大量送信・無意味スパム対策**:
  - 単位時間内に同一メールアドレスから大量送信された場合は **Gemini API を使わず無条件で迷惑メール分類**（デフォルト：10分間に8通以上）
  - 異なる送信元アドレスでも **同一内容（URL/数字差分を吸収）が60分以内に3通以上** 届いた場合は **API を使わず無条件で迷惑メール分類**
  - 空メール・ランダム文字列・文字化け・脈絡のない無意味な文章もスパムとして迷惑メール分類（添付付き・返信/転送・画像メインメルマガの誤爆防止あり）
  - 確信度 `0.85` 以上の明確なフィッシングのみ「迷惑メール」へ自動移動
  - 確信度 `0.60〜0.84` のグレーなメールは移動せず **オレンジ色でハイライト**
  - APIエラー・オフライン時はフェイルセーフで受信トレイに残します
  - 信頼済みドメインのホワイトリスト対応（SPF/DKIM認証チェック付き）

## セットアップ手順

### 1. Gemini API キーをキーチェーンに保存
Google AI Studio (https://aistudio.google.com/apikey) で取得した API キーを保存します。

```bash
cd mail-phishing-filter
./setup.sh set-key
```

### 2. 既存受信トレイで試し判定（ドライラン）＆差分スキャン
実際に移動する前に、現在の受信トレイの最新メールで判定精度を確認できます。

```bash
python3 scan_inbox.py --dry-run --limit 15
```

問題なければ `--apply` で溜まっている分を一括振り分けすると、**アカウントごとの最新メール受信日時（秒単位）**が `~/.config/mail-phishing-filter/scan_state.json` に保存されます。2回目以降は前回日時以降の新着だけを高速にスキャンします。

```bash
python3 scan_inbox.py --apply --limit 30
```

2回目以降（前回日時以降の新着のみ処理）：

```bash
python3 scan_inbox.py --apply
```

補助オプション：
- Mail.app で選択中のメールだけ即テスト：`python3 scan_inbox.py --selected --dry-run`
- 保存済みの前回日時をリセット：`python3 scan_inbox.py --reset-state`

### 3. メール.app のルールに組み込む
スクリプトを現在の配置パスでコンパイルし、Mail.app の専用フォルダへ配置します。

```bash
./setup.sh install
```

その後、Mac の「メール」アプリで以下を設定します:
1. メニュー **「メール > 設定... > ルール」** を開く
2. **「ルールを追加」** をクリック
3. 説明: `AIフィッシング自動振り分け`
4. 条件: **「すべてのメッセージ」**
5. 操作: **「AppleScriptを実行」** → **`PhishingFilter`** を選択
6. **「OK」** をクリック

## よく使うコマンド

- 状態確認: `./setup.sh status`
- 日別の稼働実績・迷惑メール振り分け一覧: `./setup.sh stats 7`
- 判定ログの確認: `./setup.sh logs 20`
- バックグラウンド定期差分スキャン有効化（5分おき・Mail.app起動中のみ）: `./setup.sh enable-auto 300`
- バックグラウンド定期差分スキャン無効化: `./setup.sh disable-auto`
- 信頼済みドメイン追加: `./setup.sh allow example.co.jp`
- 設定ファイル: `~/.config/mail-phishing-filter/config.json`
  - `model`: デフォルト `gemini-3.5-flash-lite`（さらに精度重視なら `gemini-4-hydrogen` に変更可能）
  - `junk_confidence_threshold`: 迷惑メール移動のしきい値（デフォルト `0.85`）
  - `action_on_suspicious`: グレー判定時の動作（`"highlight"` / `"junk"` / `"none"`）
  - `notify_on_junk`: 迷惑メール移動時に macOS 通知を表示（デフォルト `true`）
  - `batch_size`: 1リクエストにまとめる最大通数（デフォルト `10`）
  - `flood_window_seconds` / `flood_threshold`: 同一送信元の大量送信しきい値（デフォルト `600` 秒 / `8` 通）
  - `content_flood_window_seconds` / `content_flood_threshold`: 異アドレス同一内容のしきい値（デフォルト `3600` 秒 / `3` 通）
  - `dry_run`: `true` にすると判定ログのみ記録して移動しません

## プロジェクト構成

機能ごとに単一責任のモジュールへ分割しています（循環依存なし）。各モジュールの詳細な機能仕様・入出力・変更時の注意点は [mail_phishing_filter/README.md](./mail_phishing_filter/README.md) を参照してください。

```text
.
├── phishing_analyzer.py           # 単体・バッチ判定 CLI エントリポイント
├── scan_inbox.py                  # 受信トレイ差分スキャン CLI エントリポイント
├── mail_phishing_filter/
│   ├── config.py                  # 定数・設定ファイル・APIキー取得（Keychain等）
│   ├── storage.py                 # SQLite キャッシュ・バースト集計・JSONL 履歴ログ
│   ├── email_parser.py            # RFC 2822 解析・HTML/URL抽出・認証ヘッダー・正規化ハッシュ
│   ├── local_rules.py             # ホワイトリスト判定・機械的無意味メール検知
│   ├── gemini_client.py           # プロンプト・JSONスキーマ・Gemini API (SDK/REST)・リトライ
│   ├── analyzer.py                # 判定パイプライン本体（ローカル→キャッシュ→Gemini）
│   └── mail_applescript.py        # Mail.app 連携 AppleScript・差分スキャン状態管理
├── mail_rule.applescript          # Mail.app ルール用 AppleScript テンプレート
├── setup.sh                       # APIキー設定・インストール・ログ確認・ホワイトリスト管理
└── test_phishing_analyzer.py      # ユニットテスト
```

## セキュリティ設計・検証済み観点

外部から届く悪意あるメール（攻撃者が完全に制御可能な差出人・件名・本文・ヘッダー・HTML・添付ファイル名等）を起点とした攻撃に対し、以下の観点でコード監査および対策・防御テストを実施しています。

| 攻撃観点 | 対策・検証結果 |
| :--- | :--- |
| **1. 任意コード実行（RCE / コマンドインジェクション）** | `eval` / `exec` / `pickle` / `os.system` / `shell=True` は一切不使用。AppleScript の `do shell script` に渡すのは UUID 生成パスのみでメール由来の文字列はコマンド引数に入らず、`quoted form of` でクォート。Python 側 `subprocess.run` も配列引数（`shell=False`）のみ使用。 |
| **2. 行インジェクション・パストラバーサル（任意ファイル読み出し）** | Mail.app からのダンプ出力に攻撃者制御可能な件名・差出人を含めず、ファイル名も `^(msg\|sel)_\d+_\d+\.eml$` と `tmp_dir` 直下解決を厳密検証（違反行は破棄・ユニットテスト済み）。 |
| **3. SQL インジェクション** | `storage.py` の全 SQLite クエリでパラメータバインド（`?` プレースホルダ）を使用。 |
| **4. SSRF・意図しない外部アクセス** | メール本文中のリンク先 URL には一切自動アクセスしない。通信先は固定の Gemini API エンドポイント（`generativelanguage.googleapis.com`）のみ。 |
| **5. プロンプトインジェクション** | Gemini API のツール呼び出し（Function Calling / Code Execution）を無効化しているため、プロンプトインジェクションからコード実行へ発展する経路なし。Structured Output JSON スキーマで出力形式を拘束し、異常応答はフェイルセーフ（受信トレイ維持）。 |
| **6. 一時ファイル・認証情報の保護** | API キーは macOS キーチェーン（または権限分離ファイル）へ保管しコード・リポジトリに含めない。Mail.app ルールの一時 `.eml` はユーザー専用プライベート一時ディレクトリ（`path to temporary items from user domain`）へ書き出し、処理後即削除。 |
| **7. 巨大メール／巨大 HTML による DoS** | HTML・プレーンテキストの解析対象に上限（各 200KB）を設け、巨大メールでも高速・省メモリで完了するよう制御（2MB HTML テスト済み）。 |
| **8. プライバシー・公開情報管理** | Gemini Interactions API は `store=False` で呼び出し。ログ・キャッシュ・設定は `~/.config/mail-phishing-filter/` へ分離し、`.gitignore` で機密ファイル誤コミットを防止。 |

### 本ツールの前提と残存リスク（スコープ外）
- **Mail.app / OS 自体の脆弱性**: メール受信・表示を担う macOS 標準「メール」アプリ自体のゼロデイ脆弱性は本ツールの防御範囲外です（OS アップデートで対策してください）。
- **ローカル権限侵害**: すでに攻撃者が利用者の macOS アカウント権限を取得している環境（設定ファイルやスクリプトの改ざんが可能な状態）は防御対象外です。
- **判定回避（見逃し）**: 高度なプロンプトインジェクションや未知の手口により、フィッシングメールが `legitimate` と誤判定される可能性はゼロではありません。不審なリンクや添付ファイルは必ずご自身でも確認してください。
